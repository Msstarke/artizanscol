# Changelog

All notable project changes are tracked via Git commits and summarized here.

## 2026-03-10
- Reworked the unified `/account-settings.html` artist controls around a public-profile model instead of service listings: artists now edit category/mediums/budget/availability in one panel, can toggle their public artist account on or off, and get a direct profile preview link from settings.
- Updated the public discovery flow to respect artist-profile visibility by only surfacing live artist accounts in home/explore listings and by shifting `/artist-preview.html` from service offers to a profile-first booking request flow based on what the artist does.
- Refreshed the public client journey across `/index.html`, `/explore.html`, and `/artist-preview.html` with stronger trust-first copy, more premium section hierarchy, cleaner browse/filter layout, and a more decision-focused artist profile flow.
- Extended shared frontend styling in `styles/base.css`, `styles/components.css`, and `styles/pages.css` to support the new public layout system, improved button/card polish, better responsive behavior, and a global `[hidden]` rule so signed-out headers do not leak logout controls.
- Updated `js/public-home.js`, `js/explore.js`, `js/artist-preview.js`, and `js/renderers.js` to power the new UI hooks, richer artist cards, active filter summaries, improved empty states, and clearer public CTA behavior without changing backend contracts.
- Normalized the site shell across public pages: shared nav labels now match, signed-out pages show only a sign-in action, mobile now has a menu toggle, public footers use one consistent structure, fallback categories stay populated when the API returns none, and static page titles now use the `ARTIZANS.COLLECTIVE` format.
- Fixed artist service visibility after identity sync by preserving category fallbacks, migrating artist-linked service/booking/message/notification/invoice/payout references when the synced artist ID changes, and making `/artist-preview.html` default to the signed-in artist profile when no explicit artist ID is provided.

## 2026-03-06
- Replaced `/account-settings.html` with a unified signed-in workspace that combines client and artist workflows (profile, preferences, saved artists, bookings board, services manager, inbox, and notifications in one page).
- Retired split workspace routes by converting all `user/*` and `artist/*` pages into redirects to `/account-settings.html`.
- Removed legacy split workspace frontend modules in `js/user/*` and `js/artist/*`, updated shared nav/session labels to use `Workspace`, and adjusted unauthorized/auth route messaging for the unified flow.
- Hardened deployment and indexing security: removed `/account-settings.html` from `sitemap.xml`, disallowed it in `robots.txt`, added `noindex` metadata to `account-settings.html`, and extended CloudFormation with removable response headers plus optional canonical host redirect support (`RedirectFromDomainName`) and explicit 404 error cache TTLs.
- Hardened frontend injection and session handling: sanitized renderer HTML attributes/button values, added protocol-checked image URL sanitization, secured `statusBadge()` output escaping, encoded artist IDs in generated URLs/attributes, and moved app session persistence from `localStorage` to `sessionStorage` with legacy migration cleanup.
- Hardened API and edge configuration: removed API base URL runtime overrides from `window`/`localStorage`, limited mutable local AWS config fields to console metadata only, self-hosted Inter Tight font assets and removed Google Fonts includes from pages, restricted CloudFront static behavior methods to `GET/HEAD`, and added no-store cache policy/headers for auth-sensitive paths (`account-settings.html`, `js/auth.js`, `js/cognito-auth.js`) plus optional `CloudFrontWebAclArn` attachment support.
- Improved CI/CD deploy reliability signals: expanded static deploy workflow path coverage to include `assets/**`, favicon/robots/sitemap/404 files, and added explicit AWS secret preflight checks to both static and backend deploy workflows so missing credentials fail with clear actionable errors.
- Hardened static deploy workflow resolution: added explicit AWS identity verification (`sts get-caller-identity`), simplified region fallback expression, and added optional `ARTIZANS_BUCKET` / `ARTIZANS_DISTRIBUTION_ID` secrets to bypass CloudFormation output lookup when stack output resolution is the failure point.
